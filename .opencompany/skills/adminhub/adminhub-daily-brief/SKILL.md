# بریف صبح بنیان‌گذار

## قانون

**تو تصمیم نمی‌گیری و اقدامی انجام نمی‌دهی.** کارت مرتب‌کردن اطلاعات است.
اگر داده‌ای نیست، بنویس `نامعلوم` — حدس نزن.

## گام ۱ — جمع‌آوری (موازی)

```
GET {API}/admin/tickets?status=open&per_page=50
GET {API}/admin/wallet/withdrawals/pending
GET {API}/admin/dashboard/stats
GET {API}/marketplace/packages?per_page=10&sort=newest
GET {API}/health
```

و از نقش‌ها:

- بازار: چند بسته در صف بازبینی؟
- انتشار: آخرین وضعیت CI
- رشد: گزارش هفته آماده است؟
- پژوهش: یادداشت باز؟

## گام ۲ — محاسبه

| شاخص          | فرمول                                         |
| ------------- | --------------------------------------------- |
| تیکت بالای SLA | `now - created_at > 24h` و `status != closed` |
| منتظر مشتری   | آخرین پیام از ما و `status = pending`         |
| صف برداشت     | تعداد + مجموع مبلغ                            |
| صف بازار      | بسته‌های جدید ۲۴ ساعت                          |
| CI            | آخرین conclusion شاخه‌ی main                   |

## گام ۳ — نوشتن بریف

```text
بریف {تاریخ}

سه اولویت امروز:
۱. {مهم‌ترین تصمیم یا ریسک}
۲. {دومین}
۳. {سومین}

منتظر تصمیم شما ({n}):
- [مالی] برداشت ۱۲٬۰۰۰٬۰۰۰ ریال — حساب ۹۰ روزه، ۳ فروش موفق
- [بازار] رد بسته‌ی #۳۷ — قیمت ۱ ریال
- [انتشار] تگ ۱.۰.۱ — چک‌لیست کامل، CI سبز

ریسک:
- {n} تیکت بالای SLA (قدیمی‌ترین {x} ساعت)
- {اگر بود: اختلاف کیف پول}

نامعلوم:
- {چیزی که داده نداشت}
```

**محدودیت سخت: ۱۵ خط.** اگر بیشتر شد، سه اولویت را نگه دار و بقیه را به
پیوست منتقل کن.

## گام ۴ — پیگیری

- اقدام‌های جلسه‌ی قبل: انجام‌شده / عقب‌افتاده / منتفی
- تصمیم‌های بیش از ۳ روز معلق: با علامت ⚠️

## هفته‌نامه (پنجشنبه ۱۶:۰۰)

```text
هفته‌ی {تاریخ}
KPI: پاسخ < ۲ساعت ({x}٪) | حل < ۲۴ساعت ({y}٪) | CI سبز {z}٪ | محتوا {n}
انجام‌شده: ۵
عقب‌افتاده: ۲ (دلیل)
سه اقدام هفته‌ی بعد:
۱. ...
۲. ...
۳. ...
```

## ممنوعیت‌ها

- تصمیم‌گیری، تأیید، یا اقدام روی پول/داده.
- ارسال ایمیل یا پیام به مشتری.
- ساختن عدد برای پر کردن جا.
- بریف بیشتر از ۱۵ خط در بخش اصلی.
