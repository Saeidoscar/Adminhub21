# OpenCompany برای AdminHub21 — نصب، استخدام، هزینه، امنیت

> **حکم کوتاه:** بله برای **پشت‌صحنه**. خیر برای **جایگزینی تصمیم‌گیرنده**.
> OpenCompany می‌تواند هفت نقش عملیاتی AdminHub21 را با کیفیت قابل‌قبول اجرا
> کند، به شرطی که (۱) مهارت‌ها را ما بنویسیم، (۲) به API واقعی وصل باشد،
> (۳) پول و انتشار و داده پشت دروازه‌ی تأیید انسانی بماند.

نسخه‌ی بررسی‌شده: `zeenie-ai/OpenCompany` (MIT) — مهر ۱۴۰۵.

---

## ۱) چرا این ابزار، نه یک چت‌بات

| نیاز AdminHub21 | چت‌بات معمولی | OpenCompany |
| --- | --- | --- |
| اجرای زمان‌بندی‌شده (هر ۱۵ دقیقه، هر صبح) | ❌ | ✅ |
| دسترسی به API با توکن | دستی | ✅ ابزار HTTP |
| مجموعه‌ی دستور ثابت و قابل بازبینی | در پرامپت | ✅ `SKILL.md` در مخزن |
| چند نقش با مرزهای جدا | یک گفتگو | ✅ یک کارمند = یک تیم |
| اجرای محلی، داده‌ی خودت | ❌ | ✅ `~/.opencompany` |
| هزینه‌ی قابل پیش‌بینی | متغیر | ✅ مدل و سقف قابل تنظیم |

OpenCompany یک **اجراکننده‌ی کارمند** است: به هر کارمند یک شرح شغل، چند مهارت،
ابزار و یک ریتم می‌دهید. چیزی که در این مخزن ساخته شد، همان ورودی‌هاست.

## ۲) نصب

### گزینه ۱ — نصب‌کننده (ساده‌ترین)

از صفحه‌ی Releases، فایل ویندوز/مک/لینوکس را بگیرید. ویندوز ممکن است هشدار
SmartScreen بدهد چون بیلدها **امضا نشده‌اند**؛ «More info → Run anyway».

### گزینه ۲ — ترمینال

```bash
curl -fsSL opencompany.sh/install.sh | bash
company start          # → http://localhost:5678
```

داده‌ها در `~/.opencompany` می‌مانند. برای بستن: `Ctrl+C`.

### گزینه ۳ — Docker

```bash
git clone https://github.com/zeenie-ai/OpenCompany
cd OpenCompany
docker compose up -d --build
```

روی ویندوز Docker نیاز به WSL2 دارد. اگر فقط می‌خواهید ارزیابی کنید، گزینه ۱
کم‌دردسرترین است.

> **تست‌شده در این محیط؟** نه. این سندبررسی از روی مخزن و مستندات نوشته شده؛
> نصب واقعی را روی ماشین خودتان انجام دهید. اولین قدم پس از نصب:
> `Settings → Providers` و یک تست کوچک.

## ۳) اتصال مدل

سه مسیر، به ترتیب هزینه:

| مسیر | مدل | هزینه | مناسب |
| --- | --- | --- | --- |
| API ابری | GPT-5 mini، Gemini 2.5 Flash، DeepSeek | ~۰.۵ تا ۳ میلیون تومان/ماه | شروع |
| AIaaS آروان | همان خانواده‌ی OpenAI با base URL سازگار | همان بازه، پرداخت ریالی | اگر کارت ارزی ندارید |
| محلی (Ollama/vLLM) | Qwen3-30B یا کوچک‌تر | صفر توکن، هزینه‌ی سخت‌افزار | وقتی GPU دارید |

**نکته‌ی آروان:** AIaaS آروان endpoint سازگار با OpenAI می‌دهد
(`https://arvancloudai.ir/gateway/models/<model>/.../v1`). اگر OpenCompany
گزینه‌ی «OpenAI-compatible base URL» یا «Ollama/vLLM» دارد، همین را وارد
کنید؛ در غیر این صورت از OpenRouter یا ارائه‌دهنده‌ی بین‌المللی استفاده کنید.

**توصیه‌ی مدل:** نقش‌های پرتکرار (پشتیبانی، بازار، مالی) با مدل ارزان
(‏mini/Flash)؛ فقط پژوهش و بریف با مدل قوی‌تر. تفاوت کیفیت در کارهای
ساختاریافته کم است، در تحلیل زیاد.

## ۴) هزینه‌ی واقعی

برآورد بر اساس ریتم همین مخزن (۷ نقش، ~۲۰۰ اجرا در ماه، ~۴ میلیون توکن ورودی
و ~۶۰۰ هزار خروجی):

| سناریو | مدل | ماهانه (تومان) |
| --- | --- | --- |
| اقتصادی | GPT-5 mini / Gemini Flash | ۴۰۰٬۰۰۰ – ۹۰۰٬۰۰۰ |
| متعادل | mini برای اجرا + مدل قوی برای تحلیل | ۱٬۵۰۰٬۰۰۰ – ۳٬۰۰۰٬۰۰۰ |
| کامل با مدل مرزی | GPT-5/Claude Sonnet در همه‌جا | ۶٬۰۰۰٬۰۰۰+ |

**هزینه‌ی پنهان:** وقت شما برای نوشتن و اصلاح مهارت‌ها. هفته‌ی اول ~۶ ساعت،
بعد از آن ~۱ ساعت در هفته. این بزرگ‌ترین هزینه است، نه توکن.

## ۵) راه‌اندازی در پنج قدم

1. **نصب** (بخش ۲) و ساخت شرکت.
2. **اتصال مدل** و تست با یک پیام ساده.
3. **بارگذاری مهارت‌ها:** پوشه‌ی `.opencompany/skills` را در workspace باز
   کنید (یا `adminhub/` را در `server/skills/` کپی کنید) و در تب Skills
   بازبینی کنید.
4. **استخدام:** متن هر نقش از
   [`docs/company/hiring-briefs.md`](../company/hiring-briefs.md) را در Home
   بچسبانید. از **ستاد** و **پشتیبانی** شروع کنید.
5. **حالت پیش‌نویس:** یک هفته هیچ ارسال خودکاری فعال نکنید. خروجی‌ها را
   بخوانید، مهارت را اصلاح کنید، بعد آزاد کنید.

### اتصال به API

برای دمو:

```bash
docker compose -f docker-compose.demo.yml up -d
# API: http://localhost:8080/api/v1
```

توکن ادمین را یک‌بار بگیرید و در متغیر محیطی مهارت بگذارید:

```bash
curl -s -X POST http://localhost:8080/api/v1/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"email":"admin@adminhub21.com","password":"password"}' | jq -r .token
```

برای تولید: یک **کاربر سرویس جداگانه** با نقش ادمین محدود بسازید (نه حساب
خودتان) و توکن کوتاه‌عمر بدهید.

## ۶) امنیت — چیزهایی که باید قبل از استخدام بدانید

OpenCompany روی ماشین شما اجرا می‌شود و به ابزارهایی مثل **shell** و **HTTP**
دسترسی دارد. یعنی یک مهارت اشتباه یا یک دستور تزریقی می‌تواند واقعاً کار
خراب کند.

قواعد اجباری:

1. **ماشین جدا.** OpenCompany را روی لپ‌تاپ کاری با کلیدهای تولید اجرا
   نکنید. یک ماشین/کاربر مجزا، بدون `~/.ssh` و بدون `.env.production`.
2. **توکن کم‌اختیار.** کاربر سرویس با حداقل دسترسی؛ توکن کوتاه‌عمر؛
   چرخش ماهانه.
3. **بدون کلید درگاه.** هیچ کلید زرین‌پال/زیبال/سپ در محیط OpenCompany نباشد.
4. **`allowed-tools` را جدی بگیرید.** `shell` فقط برای نقش انتشار؛ بقیه فقط
   `httpRequest`.
5. **دروازه‌ی انسانی.** پرداخت، برداشت، حذف داده، دپلوی و انتشار عمومی —
   همیشه تأیید دستی. این در همه‌ی مهارت‌ها نوشته شده.
6. **بکاپ.** `~/.opencompany` را هفتگی بکاپ بگیرید (شامل حافظه و اعتبارنامه‌ی
   رمزنگاری‌شده).
7. **بازبینی لاگ.** هفته‌ای یک‌بار اجراهای کارمندها را مرور کنید: چه ابزاری
   صدا زد، چه نوشت.

حریم خصوصی: داده‌ی مشتری (ایمیل، تیکت، شماره) به مدل ابری می‌رود. اگر این
برای شما مسئله است، مدل محلی بگذارید یا فیلدهای شخصی را قبل از ارسال ماسک
کنید.

## ۷) چه چیزی را واقعاً می‌تواند انجام دهد (و چه چیزی نه)

### ✅ با کیفیت خوب

- خواندن صف تیکت و دسته‌بندی + پیش‌نویس پاسخ
- بازبینی شکلی بسته‌های بازار طبق قواعد نوشته‌شده
- تطبیق عددی کیف پول و ساخت گزارش اختلاف
- خواندن CI و نوشتن خلاصه‌ی خطا
- ساخت بریف روزانه از چند API
- پیش‌نویس محتوا و گزارش رشد

### ⚠️ با نظارت

- تحلیل رقیب (خطای استناد دارد)
- پیشنهاد قیمت (بدون داده‌ی کافی، حدس می‌زند)
- پاسخ به تیکت پیچیده‌ی قرارداد

### ❌ نه

- مذاکره‌ی سازمانی و تعهد حقوقی
- تصمیم قیمت‌گذاری
- استخدام/اخراج انسان
- هر تماس تلفنی یا حضوری
- تضمین «بدون باگ» — هیچ ابزاری این را نمی‌دهد

## ۸) جایگاه در نقشه‌ی راه

OpenCompany ابزار **فاز R1** است: بعد از اینکه محصول پایدار شد و اولین
مشتری‌ها آمدند، تیم پشت‌صحنه را می‌سازد. قبل از آن، هزینه‌ی نگهداری مهارت‌ها
بیشتر از فایده است.

ترتیب پیشنهادی: **ستاد → پشتیبانی → بازار → مالی → انتشار → رشد → پژوهش**.
بین هر استخدام یک هفته فاصله.

---

## ۹) اگر OpenCompany جواب نداد

جایگزین‌ها، به ترتیب سادگی:

1. **cron + اسکریپت Python** با یک فراخوانی LLM — ۹۰٪ ارزش، ۱۰٪ پیچیدگی.
2. **n8n** (خودمیزبان) + گره‌های HTTP و LLM.
3. **GitHub Actions زمان‌بندی‌شده** برای کارهای مخزنی (changelog، وابستگی‌ها).

مهارت‌های این مخزن مستقل از OpenCompany نوشته شده‌اند: هر کدام یک سند
دستورالعمل است که می‌شود در هر اجراکننده‌ای استفاده کرد.
