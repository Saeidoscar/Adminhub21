# AdminHub21 Desktop — نسخه‌ی نمایشی ویندوز

> یک فایل `.exe` که **کل محصول Next.js** را روی داده‌ی نمونه اجرا می‌کند: سایت
> عمومی، بازار، قرارداد، کیف پول، تیکت و ورود. بدون دیتابیس، بدون Docker، بدون
> اینترنت.

---

## ۱) چه چیزی داخل بسته است

| بخش                  | توضیح                                                 |
| -------------------- | ----------------------------------------------------- |
| پوسته‌ی Electron      | پنجره‌ی برنامه، بازکردن لینک‌های بیرونی در مرورگر       |
| Next.js (standalone) | همان اپ `apps/web` با همه‌ی مسیرها؛ در حالت production |
| API نمونه            | `dev/demo-contract.ts` روی داده‌ی `dev/demo-data.ts`   |
| داده                 | در حافظه؛ با بستن برنامه ریست می‌شود                   |

دو سرویس محلی با هم بالا می‌آیند:

```
127.0.0.1:41731   API نمونه (قرارداد Laravel)
127.0.0.1:41730   Next.js
```

پورت‌ها ثابت‌اند چون `NEXT_PUBLIC_API_BASE_URL` در زمان **build** داخل باندل
نوشته می‌شود. اگر پورت اشغال باشد، برنامه با پیام روشن بسته می‌شود.

## ۲) چه کاری می‌شود کرد

- مرور بازار، جستجو و فیلتر، صفحه‌ی هر بسته
- ورود (هر ایمیل/گذرواژه‌ای؛ کادرها از قبل پر هستند)
- `/app/contracts` — فهرست، جزئیات، بندها، امضا، دانلود PDF
- `/app/wallet` — موجودی، صورت‌حساب، شارژ، برداشت، انتقال
- `/app/tickets` — فهرست، گفتگو، پاسخ، تغییر وضعیت، تیکت جدید
- صفحات شرکت: درباره، نقشه‌ی راه، تعرفه، تغییرات، قوانین، حریم خصوصی

**حساب نمایشی:** `demo@adminhub21.test` / `demo` — هر مقدار دیگری هم پذیرفته
می‌شود.

## ۳) محدودیت‌های صادقانه

| محدودیت                      | چرا                                                                          |
| ---------------------------- | ---------------------------------------------------------------------------- |
| داده با هر اجرا ریست می‌شود   | API در حافظه است؛ عمداً ساده نگه داشته شده                                    |
| PDF قرارداد ساده و لاتین است  | فونت فارسی داخل PDF تولیدی جاسازی نشده؛ فایل فقط برای آزمودن مسیر دانلود است |
| پرداخت واقعی انجام نمی‌شود    | درگاه شبیه‌سازی شده؛ تراکنش «در انتظار» ساخته می‌شود                           |
| فایل‌های آپلودی ذخیره نمی‌شوند | سرور نمونه فایل‌سیستم پایدار ندارد                                            |
| بیلد ویندوز امضا نشده        | SmartScreen هشدار می‌دهد: More info → Run anyway                              |
| فقط ویندوز x64               | هدف فعلی همین است؛ مک/لینوکس با همان پیکربندی قابل افزودن است                |

این نسخه برای **نمایش و آزمودن مسیرها** است، نه برای کار واقعی. هیچ داده‌ای
بیرون از ماشین شما نمی‌رود و هیچ درخواستی به اینترنت زده نمی‌شود.

## ۴) گرفتن فایل

از GitHub Actions → workflow «Desktop» → آخرین اجرا → artifact با نام
`adminhub21-desktop-windows`. دو فایل خروجی دارد:

- `AdminHub21-1.0.0-x64.exe` — نصب‌کننده (NSIS)
- `AdminHub21-portable-1.0.0.exe` — نسخه‌ی بدون نصب

## ۵) ساخت دوباره

روی ویندوز (یا `windows-latest` در CI):

```powershell
pnpm install
cd desktop
npm install

node prepare.mjs          # Next standalone + باندل API + مونتاژ app/
node smoke.mjs            # آزمون دود روی همان خروجی
npx electron-builder --win --publish never
```

خروجی در `desktop/release/`.

### اجرای محلی بدون Electron

```bash
node prepare.mjs
node smoke.mjs     # سرو می‌کند، تست می‌کند، می‌بندد
```

یا دستی:

```bash
node build/demo-api.cjs &
PORT=41730 HOSTNAME=127.0.0.1 node app/apps/web/server.js
# → http://127.0.0.1:41730
```

## ۶) معماری

```
desktop/
├── main.cjs              پوسته‌ی Electron؛ دو فرزند را بالا می‌آورد و می‌بندد
├── prepare.mjs           build → باندل API → مونتاژ app/
├── smoke.mjs             آزمون دود روی خروجی (همان چیزی که CI اجرا می‌کند)
├── electron-builder.yml  NSIS + portable
├── build/icon.ico        آیکن برنامه
├── build/demo-api.cjs    (تولیدی)
└── app/                  (تولیدی) standalone Next + static + public
```

**چرا `asar: false`؟** پوسته باید دو پروسه‌ی طولانی‌عمر را از فایل روی دیسک
اجرا کند؛ پوشه‌ی معمولی این کار را ساده و قابل دیباگ می‌کند.

**چرا `desktop/` عضو pnpm workspace نیست؟** تا Electron و electron-builder در
نصب‌های Docker و CI وب نصب نشوند. `desktop` با `npm install` مستقل خودش
کار می‌کند و `package-lock.json` دارد.

**چرا API جدا از Next است؟** چون Next در حالت production باندل‌شده است و
مسیرهای `/api/v1/*` را از لایه‌ی داده‌ی Laravel می‌خواند. جدا نگه‌داشتن API
یعنی می‌توان همان `demo-contract.ts` را در مرورگر (preview) هم استفاده کرد.

## ۷) وقتی نسخه‌ی واقعی آمد

این بسته برای فروش نیست. مسیر واقعی:

1. `apps/api` روی ابر آروان (فاز R3 نقشه‌ی راه)
2. `apps/web` با `NEXT_PUBLIC_API_BASE_URL` واقعی
3. اگر اپ دسکتاپ لازم شد، همین پوسته با API واقعی و بدون `demo-contract`
