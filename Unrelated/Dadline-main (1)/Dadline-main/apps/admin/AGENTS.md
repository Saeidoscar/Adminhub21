# AGENTS.md — apps/admin (Next.js 16 — پنل مدیریت Dadline)

مکمل AGENTS.md ریشه.

> ⚠️ این فایل بر اساس معماری مشترک با `web`/`office` نوشته شده (همان Auth.js+Sanctum، همان apiClient،
> همان قانون HTTP-only به API). اگر پنل ادمین صفحات/ماژول‌های خاصی دارد که هنوز مستند نشده
> (مثلاً مدیریت وکلا، تایید مدارک، گزارش‌های مالی)، لطفاً لیست ماژول‌های فعلی را بگو تا این بخش تکمیل شود.

## نقش این app

پنل مدیریت داخلی Dadline — مدیریت کاربران، وکلا، درخواست‌های خدمات، محتوا و تنظیمات پلتفرم.

## قوانین معماری

- همان قانون سخت‌گیرانه ریشه: **هیچ اتصال مستقیم به Postgres یا ORM مستقیم**؛ فقط از طریق Laravel API نسخه‌دار `/v1/`.
- همان الگوی `apiClient.ts` (URL داخلی Docker برای Server Actions، URL عمومی برای client-side).
- Auth: Auth.js v5 + Sanctum، اما در این app احتمالاً نیاز به **بررسی نقش/role** سخت‌گیرانه‌تر از `web` دارد
  (فقط کاربران با role ادمین/اپراتور اجازه ورود دارند) — بر اساس جدول `roles` + `role_user` سمت API.
- هر action حساس (تغییر وضعیت کاربر، تایید/رد وکیل، حذف محتوا) باید:
  1. سمت سرور (Server Action یا API) permission را دوباره چک کند، نه فقط مخفی‌کردن UI سمت کلاینت.
  2. در صورت وجود audit log در API، از آن استفاده کند نه این‌که خودش state موازی نگه دارد.

## داده‌های حساس

- این app به داده‌های حقوقی/شخصی حساس (قراردادها، اطلاعات هویتی وکلا و کاربران) دسترسی دارد.
  هرگز داده حساس را در کلاینت بدون فیلتر role نمایش نده یا در لاگ/کنسول چاپ نکن.
- عملیات حذف روی موجودیت‌های حقوقی حساس باید soft delete باشد (مطابق قانون ریشه)، حتی از پنل ادمین.

## قوانین کلی کد

- کد کامل و production-ready، بدون placeholder.
- استایل/کامپوننت مشترک با `web`/`office` را از `packages/` بگیر، در admin دوباره تولید نکن.
